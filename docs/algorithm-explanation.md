# SafeLens 탐지 알고리즘 설명

## 개요

SafeLens의 현재 탐지 알고리즘은 단순히 밝은 점을 찾는 방식이 아닙니다. 여러 논문에서 제안된 숨은 카메라 탐지 원리를 휴대폰 RGB 카메라와 플래시 환경에 맞게 재구성한 방식입니다.

핵심은 다음과 같습니다.

- 렌즈가 빛을 작고 강하게 되돌려 보내는 역반사 특성 탐지
- 주변 배경과 다른 국소적 반사/대비 이상치 탐지
- 원형성, 방사 대칭성, 어두운 코어, 보조 반사 후보 교차검증
- 여러 프레임에서 반복 확인되는 후보만 신뢰

결과적으로 앱은 몰래카메라를 확정 판정하지 않고, 광학적으로 렌즈일 가능성이 있는 의심 위치를 표시합니다.

## 사용한 논문 기반 아이디어

### 1. LAPD 계열: 렌즈 역반사 탐지

LAPD는 스마트폰 ToF 센서와 광원을 이용해 숨은 카메라 렌즈의 retroreflection을 탐지하는 연구입니다. 렌즈는 일반 평면 물체보다 빛을 작고 강하게 되돌려 보내는 경향이 있습니다.

SafeLens에 반영한 내용:

- 플래시 OFF 기준 프레임 저장
- 플래시 ON 반사 프레임 캡처
- OFF/ON 프레임 밝기 차분
- 전체 화면 자동노출 변화 제거
- 후보 주변의 국소 반사 증가점 탐지

현재 앱은 ToF intensity map을 직접 사용하지 못하므로, RGB 카메라 프레임과 플래시 차분으로 LAPD의 핵심 물리 원리를 근사합니다.

### 2. NIRF / HeatDeCam 계열: 국소 이상치 검증

NIRF와 HeatDeCam 계열 연구는 단순 밝기값보다 배경과 다른 국소 반사, 열, 구조적 이상 패턴을 중요하게 봅니다.

SafeLens에 반영한 내용:

- 후보 중심과 주변 링의 밝기 대비 계산
- 중심부 하이라이트가 작고 집중되어 있는지 확인
- 렌즈처럼 원형/타원형 구조인지 확인
- 넓은 유리 반짝임이나 큰 하이라이트 감점

이 과정은 거울, 금속, 유리 표면처럼 단순히 밝게 반사되는 물체의 오탐을 줄이기 위한 단계입니다.

### 3. SCamF / CSI:DeSpy / Simultaneous Observation 계열: 반복성과 상관성

SCamF, CSI:DeSpy, Simultaneous Observation 계열 연구는 한 순간의 신호보다 반복적으로 관찰되는 상관 신호를 더 신뢰합니다. 원 논문들은 Wi-Fi 패킷, CSI, 자이로, 장면 변화와 같은 신호를 사용하지만, SafeLens는 모바일 WebView 환경에서 그런 데이터를 직접 접근하기 어렵습니다.

SafeLens에 반영한 내용:

- 한 프레임에서만 튄 후보는 바로 표시하지 않음
- 같은 위치와 비슷한 크기의 후보가 여러 프레임에서 반복될 때 표시
- 반복 확인 비율을 persistence evidence로 최종 confidence에 반영

즉, SafeLens는 무선 신호 대신 카메라 프레임 안에서 후보 위치의 시간적 안정성을 사용합니다.

## 실제 탐지 흐름

실시간 스캔은 다음 순서로 동작합니다.

```text
1. 후면 카메라 스트림 시작
2. 플래시 제어 가능 여부 확인
3. 플래시 지원 시:
   - 플래시 OFF 기준 프레임 저장
   - 플래시 ON 반사 프레임 캡처
   - OFF/ON 차분으로 국소 반사 증가점 계산
4. 플래시 미지원 또는 제어 실패 시:
   - 연속 프레임 차분 방식으로 fallback
5. 어두운 렌즈 코어 후보 생성
6. 밝은 반사 후보 생성
7. 유리/코팅 반사 후보 생성
8. 후보별 형태와 광학 evidence 계산
9. 오탐 패턴 감점
10. 독립 근거 교차검증
11. 여러 프레임에서 반복 확인되는 후보만 화면에 표시
```

## 후보 생성

알고리즘은 먼저 세 종류의 1차 후보를 만듭니다.

### 어두운 렌즈 후보

주변보다 어두운 원형 또는 타원형 영역입니다. 렌즈 중심부나 검은 렌즈 코어처럼 보이는 영역을 찾습니다.

### 밝은 반사 후보

플래시나 조명을 받아 강하게 튀는 작은 밝은 점입니다. 렌즈 표면의 역반사 후보로 봅니다.

### 유리/코팅 반사 후보

완전히 밝거나 어둡지는 않지만, 유리면 또는 렌즈 코팅처럼 주변과 다른 반사 특성을 보이는 영역입니다.

## 후보 검증 evidence

각 후보는 여러 독립 근거로 검증됩니다.

| Evidence | 의미 |
|---|---|
| 형태 | 원형/타원형에 가까운지 |
| 방사 대칭성 | 중심 기준으로 밝기 패턴이 균형적인지 |
| 주변 대비 | 후보 중심과 주변 링의 밝기 차이가 충분한지 |
| 역반사 | 플래시 ON/OFF 차분에서 국소적으로 밝아졌는지 |
| 어두운 코어 | 주변보다 어두운 렌즈 중심이 있는지 |
| 보조 반사 후보 | 어두운 코어 근처에 밝은 반사나 유리면 후보가 함께 있는지 |
| 지속성 | 여러 프레임에서 같은 위치에 반복 확인되는지 |

## 교차검증 gate

SafeLens는 한 가지 특징만 만족하는 후보를 바로 통과시키지 않습니다.

- 민감도 `보통/낮음`: 독립 evidence 최소 3개 필요
- 민감도 `높음`: 독립 evidence 최소 2개 필요
- 강한 역반사 또는 어두운 코어+대비 조합은 예외적으로 통과 가능

이 구조는 오탐을 줄이기 위해 넣은 핵심 단계입니다.

## 오탐 감점

다음 패턴은 렌즈가 아닐 가능성이 높아 감점합니다.

- 줄눈처럼 직선적인 패턴
- 나사 홈이나 환풍구처럼 반복되는 패턴
- 화면 가장자리의 불안정한 후보
- 넓은 유리 반짝임
- 큰 금속성 하이라이트
- 너무 크거나 길쭉한 영역

## Confidence 의미

앱에 표시되는 confidence는 실제 확률값이 아닙니다.

이는 후보가 렌즈 특징을 얼마나 많이, 얼마나 강하게 만족했는지 나타내는 내부 점수입니다.

```text
confidence = 형태 + 대칭성 + 대비 + 역반사 + 어두운 코어 + 보조 후보 + 지속성 - 오탐 패널티
```

따라서 confidence 80%는 “실제로 80% 확률로 카메라가 있다”는 뜻이 아니라, “현재 알고리즘 기준에서 렌즈 evidence를 강하게 만족했다”는 의미입니다.

## 현재 구현의 한계

SafeLens는 휴대폰 카메라 기반 앱이므로 다음 논문 기능을 직접 사용하지 않습니다.

- LAPD의 ToF intensity map
- NIRF의 적외선 반사장 학습 모델
- HeatDeCam의 열화상 센서
- SCamF / CSI:DeSpy / LocCams의 Wi-Fi 패킷 또는 CSI 분석
- 실제 대규모 데이터셋으로 학습한 CNN/ML 모델

따라서 현재 방식은 논문 기반 원리를 RGB 카메라와 플래시에 맞춰 구현한 실용형 근사 알고리즘입니다.

## 권장 사용 방법

- 플래시 제어가 지원되는 기기에서 실시간 스캔 사용
- 같은 위치를 2~3초 정도 안정적으로 비추기
- 너무 빠르게 움직이지 않기
- 처음에는 `보통 / 최소 신뢰도 35~45`로 테스트
- 실제 렌즈를 놓치면 `높음 / 최소 신뢰도 25~35`로 낮춰 비교
- 탐지 결과는 확정 판정이 아니라 의심 위치 확인용으로 사용

## 요약

현재 SafeLens 알고리즘은 다음 세 가지를 결합합니다.

```text
LAPD식 플래시 OFF/ON 역반사 차분
+ NIRF/HeatDeCam식 국소 이상치 검증
+ SCamF/CSI:DeSpy식 반복성 기반 신뢰도 보강
```

이 조합으로 휴대폰 RGB 카메라만 사용하는 조건에서 가능한 범위 안에서 렌즈 의심 위치를 탐지합니다.
